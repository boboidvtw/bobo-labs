Project · Browser extension · Manifest V3

Auto Resizer for YouTube™

YouTube 的播放器只會長到它自己想要的大小。1600px 的視窗上，一支 4K 影片仍然被塞在 1112px 的框裡，右邊擺著永遠佔住 400px 的推薦欄，底下是一大片空白。 這個擴充功能把順序反過來：播放器先取空間，推薦欄撿剩下的，擠不下就換行到下方。

它做什麼

  • 依畫質自動匹配尺寸 —— 以影片原生解析度為上限，再收斂到視窗容納得下的最大 16:9。
  • 螢幕適配（4K / 多螢幕） —— 依「播放器寬度 × 螢幕像素密度」推算需要的畫質並主動要求。 把視窗從 Retina 拖到 4K 外接螢幕，畫質會跟著重算。
  • 彈出式播放器 —— 控制列上多一顆按鈕，把影片丟到獨立視窗續播，視窗內只留播放器， 尺寸以閉環校正貼合影片長寬比，可指定開在哪一台螢幕。
  • 畫質鎖定 —— 每支新影片自動鎖到你指定的畫質；影片沒有時取可用的最高畫質。
  • 零留白版面 —— 消除播放器兩側與上方的留白。

隱私

不收集任何資料。沒有分析工具、沒有遠端程式碼、沒有任何對外連線 —— 整份原始碼裡連一個 fetch 都沒有。你的設定存在瀏覽器自己的 chrome.storage.sync，經由你的 Google 帳號同步，開發者看不到。

技術細節

Manifest V3、零相依、零建置流程。畫質偵測與畫質控制各自跑在 YouTube 頁面的主世界， 版面套用留在隔離世界，三者只透過事件與 postMessage 溝通。 單元測試以 Node 內建的 test runner 加 node:vm 執行， 端到端測試則真的啟動一個瀏覽器實例、載入擴充功能、對真實 YouTube 量測放大幅度。

兩個踩過的坑值得記下來：macOS 的 chrome.system.display 完全不提供 DPI （dpiX 恆為 0），而 Brave 的指紋防護會竄改網頁端看到的 screen.* —— 任何需要真實螢幕尺寸的邏輯都不能寫在 content script 裡。
