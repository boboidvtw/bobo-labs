發布前先驗收：Epoch RTS v0.5.0 與 3489 行音效 ERROR

開工檢查時發現，試玩包連結指向的 Release v0.4.0 不含最近做完的 16 個時代。 照原計畫發給試玩者，他們測到的會是舊版。我先停下來發了 v0.5.0， 再把遊戲內一直跳 ERROR 的原因查清楚：3489 行錯誤，扣掉音效相關後剩 0。

為什麼不能直接把試玩包發出去

M7.6 是第一輪外部試玩。我對照試玩包文件與 GitHub Release，發現 v0.4.0 的資產是在 16 時代 （A1–A4）合入之前打包的，但 INSTALL 與試玩包連結仍指向它。 如果照發，回饋會落在舊版上，之後還得逐條判斷「這個問題是不是已經修了」。

v0.5.0 怎麼證明是對的版本

發布前把 mod.json 從 0.4.0 升到 0.5.0，測試用的 t13-harness 依賴同步改。 回歸跑了六組：t04 183 項、t05 77 項、ages 185 項、ages-early 48 項， 加上 duel 與 duel-ai（seed 42，遊戲內時間 7 = 1106 秒、1126 秒）。 整套 12 場模擬不到 2 分鐘就跑完，因為 smoke-macos 是非視覺模擬，duel-ai 的秒數是遊戲內時鐘，不是真實時間。

打包用 package-mod.py，產出 92 個檔、112,334 bytes。接著做三次比對： 在 tag 上重新建置，雜湊與原包相同；GitHub 上的資產 digest 與本機相同； 重新下載後 shasum -c 回 OK。三個獨立來源都對得上，才算「發出去的就是測過的」。

3489 行 ERROR 其實是音效

用 --menu 開遊戲，親手點對戰設定「玩家」分頁的 Start Age 與 End Age： 史前開局、結束在文藝復興，行為正確。但 console 一直跳 ERROR。 把 mainlog 去掉 HTML 標籤後過濾，扣掉 OpenAL 與 ogg 相關行，剩下 0 行。 根因是 macOS 預設輸出裝置是一台 Philips 電視（HDMI），OpenAL 初始化時沒有回應。

自動測試一律帶 -nosound，所以從來沒碰過這條路徑。 這提醒我：測試環境與玩家環境差在哪裡，就是會漏的地方。 試玩者若同樣用 HDMI 電視當預設輸出，很可能也會看到這些 ERROR；這是我的推測，尚未找人驗證。

文件也要對照實作檢查

age-ladder.md 原本寫史前開局的長矛兵「要到青銅才能訓練」，我去查模板， 實際條件是 phase_epoch_copper，也就是銅器時代。文件已更正。 文件裡的條件，之後發布前要抽幾條對回模板。

發布前先核對連結指向的版本：功能做完不等於 Release 含有它。試玩包、INSTALL、tag 三處要指向同一版。

用多個獨立來源證明同一個包：tag 重建、GitHub digest、重新下載比對，三者一致才算驗證過。

先過濾已知雜訊再判斷 ERROR 數量：扣掉 OpenAL／ogg 後是 0，3489 行才從「遊戲壞了」變成「音效裝置的問題」。

測試參數會掩蓋玩家環境：-nosound 讓自動測試永遠避開音效路徑，必須有人用預設設定實機跑一次。

文件條件對回實作：「到青銅才能訓練」與 phase_epoch_copper 差一個時代，只有查模板才抓得到。
